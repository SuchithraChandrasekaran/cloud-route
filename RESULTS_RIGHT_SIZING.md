# Right-sizing evaluation results

Generated by `python -m agent.evaluate_right_sizing` on 2026-10-21. Every number below comes from that run.

## What is being tested

The engine computes a suggested CPU and memory request for each workload from its measured usage: `max(floor, round_up(usage x headroom, step))`. This evaluation checks that arithmetic against answers computed separately with plain integers, over 1000 random cases per check (seed 0).

| Check | What it verifies | Result |
|---|---|---|
| Suggestion matches an independent computation | CPU and memory suggestions equal max(floor, round_up(usage x headroom, step)) computed with integers only, over random usage and headroom. | 2000/2000 |
| Suggestion has the required properties | Never below the floor, never below usage x headroom, always a multiple of the step, and never one step larger than needed. | 2000/2000 |
| More usage or more headroom never lowers the suggestion | For random pairs, the suggestion is non-decreasing in usage and in headroom. | 1000/1000 |
| Status matches the request-versus-suggestion comparison | Lowered, below measured use, or no change, from the requested value and the independently computed suggestion. | 1000/1000 |
| A suggestion applied as the request gives no change | Using the suggested values as the requests and measuring the same usage reports 'no change'. | 1000/1000 |
| Quantities from the cluster parse correctly | CPU in n, u, m or whole cores; memory in Ki, Mi, Gi or bytes, converted to millicores and MiB exactly. | 1000/1000 |
| A workload without a full reading gets no suggestion | If either CPU or memory usage is missing, no suggestion is made. | 100/100 |

Deliberately wrong versions (no floor, rounding down, no headroom, an off-by-one step) are run in `tests/test_evaluate_right_sizing.py`; each one is caught by these checks.

## Limits of this evaluation

- It shows the arithmetic is computed as stated. It does not show the rule is a good one: the headroom factor of 1.5, the floors and the steps are policy choices.
- It does not show that following a suggestion saves money or keeps a workload healthy.
- Measured usage comes from one snapshot of the cluster's metrics service, which is not peak usage. On the idle bank-easy demo every suggestion is the floor value.
- The reading of the live cluster is cross-checked by hand against `kubectl top`; that observation is recorded in `docs/right-sizing-live-check.md`, not regenerated here.
