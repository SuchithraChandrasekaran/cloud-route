# Residency check results

Generated by `python -m agent.evaluate_residency` on 2026-10-21. Every number below comes from that run.

**Bank platform dataset: passed. Random graphs: 200/200 passed.**

For each graph the engine's residency check is compared with lists computed independently in plain Python: components outside the allowed regions, dependencies that cross a region boundary, and components with no region. Two more checks run on every graph: a component with no region is never flagged, and adding region labels never changes the migration plan.

## Limits

- Regions are declared labels, not observed data placement. These checks test the engine's logic on labels. They do not show that any data really sits in a region.
- The labels on the bank dataset come from the fixed rule above, not from a real deployment. Only 7 of its components are deployed, and on the live cluster the demo labels are set by hand.
- The random graphs are synthetic.
- The expected answers are computed independently of the engine, but by the same author. A shared misreading of the rule would pass both. The rule is simple: set membership and a comparison of two labels.
- A component with no region is reported on its own list. It is never judged compliant or non-compliant.
